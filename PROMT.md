# BALENCIAGA INFRASTRUCTURE DIVISION — GOLDENROUTE FW

---

## ОСНОВНЫЕ ПОЛОЖЕНИЯ

GOLDENROUTE — ЭТО НЕ ПРОКСИ. ЭТО ИНФРАСТРУКТУРНАЯ ДИСЦИПЛИНА.

Система принимает ровно 3 (три) решения о каждом входящем пакете:

1. **Destination в `russian-ips`** → RETURN. Трафик идёт напрямую. Российские адреса не требуют посредников.
2. **Destination в `tor-exclude`** → RETURN. Ваш персональный список исключений. Вы сами решаете, что не должно касаться Tor.
3. **Всё остальное** → REDIRECT `:12346` → Tor. Без обсуждений. Без альтернатив.

Балансировка между wstunnel и Tor — концепция, признанная несостоятельной. Единственный бэкенд. Единственное направление. Tor.

---

## 1. ТРИ ЦЕПОЧКИ — ТРИ ПРАВИЛА ДИСЦИПЛИНЫ

### 1.1. `FW_REDIRECT` — PREROUTING

Встречает трафик от LAN-клиентов на входе в хост. Применяется ДО того, как ядро решит, куда направить пакет.

Порядок проверки (нарушение порядка — фатальная ошибка):

1. `dst-type LOCAL` → RETURN. Пакеты, адресованные самому хосту, не должны быть тронуты.
2. `src 172.16.0.0/12` → RETURN. Docker-контейнеры. Без этого правила возникает петля: трафик от Tor/unbound к внешнему миру снова перехватывается и направляется в себя. **ПЕТЛЯ ПРОКСИ** — единственная ошибка, которая превращает работающую систему в 504 Gateway Timeout.
3. Приватные диапазоны (10/8, 172.16/12, 192.168/16) → RETURN.
4. `match-set russian-ips dst` → RETURN. Домашняя территория.
5. `match-set tor-exclude dst` → RETURN. Ваши исключения.
6. `dport 12346` или `9050` → RETURN. Сам redsocks-tor и Tor. Не перехватывать свой же трафик.
7. `dport 53` (UDP/TCP) → REDIRECT `:53`. DNS-запросы перехватываются и направляются в unbound. Даже если клиент прописал 8.8.8.8 вручную.
8. Всё остальное TCP → REDIRECT `:12346`. Приговор приведён в исполнение.

### 1.2. `FW_OUTPUT` — OUTPUT

Абсолютно та же логика, что и FW_REDIRECT, но для трафика, рождённого процессами на самом хосте.

Хост не является исключением. Хост подчиняется тем же правилам.

### 1.3. DOCKER-USER — FORWARD

Разрешает транзитный трафик из LAN-подсети. Без этого правила FORWARD policy DROP отбрасывает любой транзитный трафик, и клиенты из LAN не выходят в интернет.

Два правила:
- `-s LAN_CIDR -j ACCEPT`
- `-d LAN_CIDR -j ACCEPT`

И одно правило MASQUERADE в POSTROUTING для SNAT.

## 2. КОМПОНЕНТЫ

### 2.1. `fw` — единственный сервис, имеющий власть

`network_mode: host`. Не потому что так удобно. ПОТОМУ ЧТО ИНАЧЕ ПРАВИЛА НЕ РАБОТАЮТ.

Права: `NET_ADMIN` + `NET_RAW`. Управляет iptables на хосте напрямую, без посредников.

При старте выполняет:
1. Очистка старых цепочек `FW_REDIRECT` и `FW_OUTPUT` (while-цикл: удаляем, пока удаляется). Идемпотентность — обязательное требование.
2. Загрузка `russian-ips` из файла. Фоновое обновление с RIPE (4 попытки, таймаут 30s).
3. Загрузка `tor-exclude` из файла.
4. Запуск `redsocks` на порту 12346, апстрим — Tor SOCKS5 на порту 9050.
5. Применение правил к OUTPUT и PREROUTING.
6. QUIC-блокировка (см. раздел 5).
7. Бесконечный sleep. Контейнер держится в живых, пока не будет остановлен.

При остановке: trap cleanup убивает redsocks и завершается без оставления следов.

### 2.2. `tor` — единственный бэкенд

SOCKS5 на порту 9050. Мосты obfs4 для обхода блокировок. Никакой балансировки, никаких альтернатив.

Tor принимает трафик от redsocks и отправляет его в мир. Snowflake не работает через Docker NAT — используйте obfs4.

### 2.3. `unbound` — DNS без компромиссов

Перехватывает все DNS-запросы на порту 53. Форвардит через DoT (DNS-over-TLS):
- `.ru` → Яндекс DNS (77.88.8.8, 77.88.8.1)
- Всё остальное → Cloudflare (1.1.1.1) + Google (8.8.8.8)

## 3. ДАННЫЕ

### 3.1. `fw/russian-ips.txt`

IPv4-диапазоны РФ. Источник: RIPE API. Обновляется автоматически при каждом запуске `fw`. Не редактировать вручную — будет перезаписано.

Размер: ~11000 записей. Загружается в ipset `russian-ips` типа hash:net.

### 3.2. `fw/tor-exclude-ips.txt`

Ваш персональный список исключений. Формат: один IP или CIDR на строку, `#` — комментарий.

Всё, что попадает в этот список, НЕ направляется в Tor. Полезно для:
- Сервисов, блокирующих Tor exit-ноды
- Сервисов, требующих прямой доступ без задержек Tor
- IP-адресов, которые должны быть доступны напрямую вне зависимости от геолокации

## 5. QUIC — ПРОТОКОЛ, КОТОРЫЙ ДУМАЕТ, ЧТО ОН ВЫШЕ TCP

QUIC (UDP/443) — протокол, который браузеры предпочитают TCP. Прокси-серверы не поддерживают перехват UDP. Если QUIC не заблокировать, браузер установит прямое соединение с иностранным сервером, минуя Tor.

Решение: блокировка QUIC для всего, что не в `russian-ips` и не в `tor-exclude`.

```
FORWARD:  UDP/443 !russian-ips !tor-exclude → DROP
OUTPUT:   UDP/443 !127.0.0.1 !russian-ips !tor-exclude → DROP
```

Браузер, не получив ответа по UDP, откатывается на TCP/443. TCP/443 перехватывается правилами PREROUTING/OUTPUT и направляется в Tor.

## 6. ТРЕБОВАНИЯ К СРЕДЕ

- Linux с модулями ядра: `ip_tables`, `iptable_nat`, `ip_set`, `ip_set_hash_net`
- Docker + Docker Compose
- `ip_forward = 1` на хосте
- Порт 53 должен быть свободен
- Сетевой интерфейс для LAN (опционально, только для форвардинга клиентов)

## 7. ПОЛНЫЙ ПУТЬ ПАКЕТА

### Запрос к yandex.ru с LAN-клиента (российский адрес):

Клиент → хост → PREROUTING: dst russian-ips? ДА → RETURN → FORWARD (ACCEPT) → POSTROUTING (MASQUERADE) → интернет → yandex.ru

DNS: клиент → PREROUTING: dport 53? ДА → REDIRECT :53 → unbound → DoT → Cloudflare/Google

### Запрос к opencode.ai с LAN-клиента (иностранный адрес):

Клиент → хост → PREROUTING: dst russian-ips? НЕТ → dst tor-exclude? НЕТ → dport 53? НЕТ → REDIRECT :12346 → redsocks → socks5 127.0.0.1:9050 → Tor (мосты obfs4) → интернет → opencode.ai

### QUIC к иностранному сайту с LAN-клиента:

Клиент → хост → FORWARD: UDP/443 !russian-ips !tor-exclude → DROP → браузер откатывается на TCP/443 → PREROUTING: REDIRECT :12346 → Tor

## 8. ДИАГНОСТИКА

### Tor не забутстрапился

```bash
docker compose logs tor | grep "Bootstrapped"
```

Ожидается: `Bootstrapped 100% (done)`. Если нет — мосты устарели. Получить свежие на https://bridges.torproject.org.

### Трафик не идёт через Tor

```bash
docker compose exec fw iptables -t nat -L FW_REDIRECT -n -v
```

Счётчик на правиле `REDIRECT tcp --dport 12346` должен расти.

### QUIC не блокируется

```bash
docker compose exec fw iptables -L FORWARD -n -v | grep "udp dpt:443"
```

Счётчик на правиле DROP должен расти при обращении к иностранным сайтам.

## 9. ПРАВИЛА РАЗРАБОТКИ

1. **Идемпотентность.** Любая операция должна быть повторяема без ошибок. while-циклы удаления правил перед добавлением.
2. **Graceful degradation.** RIPE недоступен — используем кеш. Tor недоступен — трафик не уходит (но система не падает). Список исключений пуст — весь иностранный трафик идёт в Tor.
3. **Минимум зависимостей.** Alpine + iptables + redsocks + curl + jq + ipset. Всё.
4. **Прозрачность для клиента.** Ни одно устройство в LAN не требует настройки прокси. Шлюз и DNS — единственное, что нужно указать.

## 10. ЧТО ЗДЕСЬ НЕ РЕАЛИЗОВАНО (И НЕ БУДЕТ)

- IPv6. Только IPv4.
- Балансировка между несколькими Tor-инстансами.
- UDP-прокси (не поддерживается SOCKS5).
- Snowflake bridges (не работают через Docker NAT).
- Hot-reload конфигурации (перезапуск контейнера).
